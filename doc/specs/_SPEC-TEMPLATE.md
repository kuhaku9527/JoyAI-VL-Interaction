## 1. 因果链（Why / Why-this-choice）

- **Problem**：要解决什么。不要只描述症状，要点出决策态与运行态 / 需求之间的张力。
- **Why this choice**：为什么选这个范式 / 方案；它解决了什么、付出了什么。
- **被否方案及理由**：列 1–N 个曾被考虑但否决的方案，及否决原因。**这是负面约束的因，必写。**

## 2. 范围

- **做什么**：本 spec 覆盖的决策点。
- **不做什么（负面约束）**：明确不能做 / 不选什么，及为什么（从 §1 被否方案延展）。*不得在此写 bug 修复 / 验证 / 运维步骤。*

## 3. 设计（核心决策点）

- 关键决策 1：…（含 why）
- 关键决策 2：…（含 why）
- （按需展开；每个决策点都应能回溯到 §1 因果链。）

> - 实现 / 验证涉及「跨 ≥2 任务或 ≥2 agent 复用」的流程；或
